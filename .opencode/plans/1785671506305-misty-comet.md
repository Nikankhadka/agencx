# Model reliability: OpenRouter primary + Z.ai free fallback

## Goal

Portfolio demo, free-only stack. Keep OpenRouter `google/gemma-4-26b-a4b-it:free` as the primary (proven: structured outputs + tools + 0 reasoning tokens), and add an automatic **failover to Z.ai's free `glm-4.7-flash`** so a transient OpenRouter 429 / upstream failure no longer kills a turn. The user supplies a Z.ai key; the app degrades gracefully when none is configured.

## Why this shape

- `get_llm_provider()` (`app/llm/dependency.py`) is the single seam every surface uses (chat, onboarding, evals). A `FailoverProvider` wrapper there covers everything at once.
- Z.ai's structured output is **only documented as `{"type":"json_object"}`** (schema in the system prompt), not the strict `json_schema` that `OpenAISDKProvider.extract` sends via `.parse()`. So the fallback provider needs a `json_object` extract mode.
- Z.ai free `glm-4.7-flash` has thinking **default ON** (the reasoning-tax that makes your demo slow) - the fallback must send `thinking: {type: disabled}`.
- Failover must be **optional**: no fallback env vars set (CI, tests, no-key dev) means the existing single-provider path, byte-for-byte unchanged.

## Files to change

### 1. `backend/app/core/config.py` - add fallback settings
Three new fields (default empty = failover disabled):
```python
llm_fallback_base_url: str = ""
llm_fallback_api_key: str = ""
llm_fallback_model: str = ""
```

### 2. `backend/app/llm/openai_base.py` - two knobs on the shared base
- `OpenAISDKProvider.__init__` gains `extra_body: dict[str, object] | None = None` and `json_object_extract: bool = False` (both default off - Azure/OpenRouter/gemma behavior unchanged).
- Add `_extra_body_kwargs()` returning `{"extra_body": ...}` when set, else `{}`; spread it into `_chat_with_tools_native`, `chat`, `chat_stream` `_open`, and `extract`.
- In `extract`, when `json_object_extract`: append `schema.model_json_schema()` to the system prompt, call `create()` with `response_format={"type":"json_object"}`, then `schema.model_validate_json(content)`. Malformed JSON raises pydantic `ValidationError` -> the existing `_with_retry` resamples it. Unchanged for the non-json_object path.

### 3. `backend/app/llm/zai.py` - NEW: Z.ai fallback provider
`ZaiOpenAICompatProvider(OpenAISDKProvider)`:
- Builds `AsyncOpenAI(base_url=settings.llm_fallback_base_url, api_key=..., timeout=SDK_TIMEOUT)`.
- Passes `model=settings.llm_fallback_model`, `json_object_extract=True`, `extra_body={"thinking": {"type": "disabled"}}`, native `supports_tools=True` (Z.ai Flash supports function calling).
- Docstring records why json_object (Z.ai documents only json_object, not json_schema) and why thinking is disabled.

### 4. `backend/app/llm/failover.py` - NEW: `FailoverProvider(LLMProvider)`
Wraps `primary` + `fallback`. Transient set: `RateLimitError`, `UpstreamResponseError`, `httpx.HTTPError` (network/connect/timeout), pydantic `ValidationError`.
- `extract`, `chat`, `chat_with_tools`: try primary; on transient, run fallback. (Primary's internal 3x retry runs first, so failover is only reached after it's genuinely exhausted.)
- `chat_stream`: async generator; fail over only on the **first** delta's error (mid-stream can't retry without duplicating tokens); after a token flows, propagate.
- Does NOT fail over on `LimitTimeout` (that's the tenant budget, not a provider failure).

### 5. `backend/app/llm/dependency.py` - wire it
```python
def get_llm_provider() -> LLMProvider:
    settings = get_settings()
    primary = OpenAICompatProvider(settings) if settings.llm_provider == "openai_compat" else AzureOpenAIProvider(settings)
    if settings.llm_fallback_base_url and settings.llm_fallback_model:
        return FailoverProvider(primary, ZaiOpenAICompatProvider(settings))
    return primary
```

### 6. Env files
- `backend/.env`: align primary to `LLM_MODEL=google/gemma-4-26b-a4b-it:free` (kills the demo-vs-CI drift), add a Z.ai fallback block (`LLM_FALLBACK_BASE_URL=https://api.z.ai/api/paas/v4/`, `LLM_FALLBACK_MODEL=glm-4.7-flash`, `LLM_FALLBACK_API_KEY=` - user fills in).
- `.env.example`: document the fallback vars + Z.ai free Flash models + the gemma primary.

### 7. Tests (new)
- `backend/tests/test_llm_failover.py`: primary raises 429/UpstreamResponseError -> fallback answer returned, fallback untouched on success; both fail -> error propagates; `chat_stream` first-delta failover.
- `backend/tests/test_llm_zai.py` (or extend `test_llm_provider_retry.py`): json_object extract calls `create` with `response_format={"type":"json_object"}` + thinking extra_body, parses+validates, resamples on malformed JSON.
