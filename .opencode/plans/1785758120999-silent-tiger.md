# Swap OpenRouter model gemma-4 -> gpt-oss-20b:free (gated on live verification)

## Context

User wants to switch the OpenRouter model from `google/gemma-4-26b-a4b-it:free` to `openai/gpt-oss-20b:free`.

**Suitability check result (done in planning):**
- Live `openrouter.ai/api/v1/models` today: `openai/gpt-oss-20b:free` exists, $0 pricing, advertises `structured_outputs`, `tools`, `tool_choice`, `reasoning`/`include_reasoning`.
- BUT the repo measured this exact model twice and it failed the hard requirement: `decisions-log.md:193` (2026-07-11, "ignores json_schema and returns plain text") and `.agents/memory.md:23` (2026-07-29 benchmark, "gpt-oss-20b FAILS structured output (ValidationError - disqualifying)"). Every route and inspection call in Wren is a strict-JSON `extract()` (`backend/app/llm/openai_base.py:400-442`, `client.chat.completions.parse` with `response_format=schema`), so a model that ignores json_schema breaks every turn.
- Also flagged: gpt-oss-20b advertises reasoning; memory line 19 warns reasoning models are a latency bad fit (gemma emits 0 reasoning tokens).
- User decision: **live-verify first, swap only if the probe passes.**

## Phase A: Live verification probe (the gate)

Write a throwaway probe `backend/_probe_gpt_oss.py` (delete after run; do not commit). It must drive Wren's own code path, not a raw curl:

1. `Settings(llm_model="openai/gpt-oss-20b:free")` - base URL / API key come from `backend/.env` automatically (real OpenRouter key, never printed).
2. `OpenAICompatProvider(settings)` (`backend/app/llm/openai_compat.py`) - same provider CI/demo use.
3. Run 5 trials of `extract()` with a RouteDecision-shaped pydantic schema (Literal intent field + optional `customer_ref: str | None` + `rationale: str`) - mirrors `supervisor.RouteDecision` usage.
4. Run 1 plain `chat()` call (prose path) and 1 `chat_with_tools()` call (gpt-oss advertises tools; native path).
5. Print per-call success/failure, latency, and usage (look for `reasoning_tokens` / `completion_tokens_details` to assess the reasoning-model risk).
6. Note: `_extract_strict` already retries 3x internally; `_with_retry` includes the OpenAI SDK validation errors.

**Pass criteria (all must hold):**
- All 5 extract trials return valid parsed pydantic objects (no ValidationError / ValueError / UpstreamResponseError / "no parseable structured output").
- `chat()` returns text; `chat_with_tools()` returns a sane ToolTurn.
- Report reasoning token usage (if it emits hidden reasoning by default, flag it to the founder before swapping - per conventions, don't silently accept a known-bad-fit; the swap decision is already made, but the latency tradeoff must be documented).

**If the probe fails** (any extract trial fails the way the July 11 / July 29 records describe): stop, keep gemma everywhere, and append a dated re-check entry to `docs/archive/decisions-log.md` so the record stays current.
