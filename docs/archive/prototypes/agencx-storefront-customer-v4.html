Proposed - mobile (no-photo base, photos-mature)

Frame 1 is the base foundation with Photos off; flip the toggle to see the same page mature. Rows are content-sized - no reserved slot, so a no-photo menu is compact by construction. The identity block carries the business facts that already exist in the tenant profile (type, hours, services). The header carries the single chat entry; tapping the business identity scrolls back to top, and item-level questions stay with the items ("Ask about this"). Tap any row to open its detail sheet, or the header icon to open chat.

Decisions to settle in this review

Each answer queues one prompt back to the agent. Annotate anything else directly on the frames.

1. Hero fallback when there is no cover photo

Applies to every tenant who never uploads a cover - including Sababa today.

2. Offering list layout

Currently the app uses a two-column grid at sm+; Uber Eats uses a single column. Both are shown above.

3. Which profile facts to publish

Already in tenant_config.profile; exposing them is a small public-API addition. Contact is deliberately excluded (privacy).

Notes and open questions

  • Minimal business (no offerings): the page shows the name, a brief description, the default facts onboarding collects (type, hours) and the assistant's sakura panel with a Reply action, spread over the full page - hero on top, panel in the middle, footer at the bottom. No "nothing published" / "no data" copy anywhere - on a business-agnostic platform that would read as questioning the business's validity.
  • Chat entry: one persistent chat button in the header (as today); the header business identity taps to scroll back to top; item-level questions stay in the detail sheets ("Ask about this"). No fixed bottom bar.
  • Ask about this in the detail sheet seeds the composer exactly as today ("Tell me about {offering}").
  • Not touched: chat internals, quoting/order lookup (chat-driven), offering search (RF-3), owner-side image workflow (RF-5), desktop chat side panel (RF-8 stays deferred).
  • Not in this prototype: ratings/reviews (no data exists), delivery/pickup toggle (Agencx is not a delivery marketplace), cart/checkout.
  • No new tokens or dependencies are planned. If a visual value here is not expressible on the token scale, it gets a founder ruling plus a token before implementation.
  • Demo photos are Wikimedia Commons images used only to preview the mature state; real tenants bring their own via Cloudinary.
